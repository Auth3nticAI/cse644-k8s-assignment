=== [1] ClusterIP - internal-only ====================================
Who can reach it   : only clients inside the cluster (Pods), or an
                     operator tunneling in with kubectl port-forward.
Entry point        : the Service's ClusterIP (10.96.x.x), a virtual
                     IP that only exists in the cluster's networking.
Forwarded by       : kube-proxy (iptables/nftables rules on every
                     node) rewrites the ClusterIP:port to a live
                     Pod endpoint IP:port.

Access test: kubectl port-forward (operator-local access, no
cluster-network membership required):

[PASS] ClusterIP reachable via kubectl port-forward

=== [2] NodePort - fixed port on every node ===========================
Who can reach it   : anything that can reach any cluster node's IP on
                     the high port (30080 here) - e.g. other hosts on
                     the same LAN as the node, not just cluster-internal.
Entry point        : port 30080 on EVERY node (kube-proxy opens it
                     cluster-wide, regardless of which node runs the Pod).
Forwarded by       : kube-proxy on whichever node received the
                     connection, to a live Pod endpoint (possibly on
                     a different node).
Local access path  : KinD's extraPortMappings map host port 30080 ->
                     the control-plane container's port 30080.

$ curl http://localhost:30080/
HTTP 200
[PASS] NodePort reachable at localhost:30080

=== [3] LoadBalancer - external IP from cloud-provider-kind ===========
Who can reach it   : anything that can route to the assigned external
                     IP - in a real cloud, the public internet; here,
                     anything on the 'kind' Docker bridge network.
Entry point        : the EXTERNAL-IP cloud-provider-kind assigned
                     (an Envoy proxy container it runs for this Service).
Forwarded by       : that Envoy container proxies to the Service's
                     Pod endpoints - kube-proxy is not in this path.
EXTERNAL-IP: 172.22.0.4

NOTE: on Docker Desktop for Windows, the WSL2 distro's own network
namespace has no route into the 'kind' custom bridge network (this
is a Docker-Desktop-on-Windows networking limitation, not a
Kubernetes one), so the access test below runs from a peer container
already attached to that network (cse644-worker) rather than from
the WSL2 shell directly:
$ docker exec cse644-worker curl http://172.22.0.4:8090/
HTTP 200
[PASS] LoadBalancer EXTERNAL-IP reachable on the kind Docker network

=== [4] Ingress - HTTP host/path routing ==============================

Forwarded by       : the ingress-nginx controller reads the Ingress
